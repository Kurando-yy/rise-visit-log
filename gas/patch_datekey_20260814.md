# ライズ来店記録GAS 日付キー修正パッチ（2026-08-14 大神）

**症状**：来店記録03_タブレット に同じ日が何行も増える／曜日が空／朝の件数が常に0。

**原因（1つ）**：明細タブの `日付` 列は**日付データ**なのに、コードが `String(...)` で文字にしている。
```js
String(日付データ)  →  'Tue Aug 11 2026 00:00:00 GMT+0900 (Japan Standard Time)'
ymd_(日付)          →  '2026-08-11'
```
**この2つを比べているので、絶対に一致しない。**

★**書き込む形を揃えるだけでは直らない**（"2026-08-11" と書いても Google が日付データへ自動変換して戻る）。
**比べる時に正規化する**のが正解。

---

## 直す箇所は4つ（すべて同じ直し方）

### ① ヘルパを1つ追加（`ymd_` の隣に置く）

```js
/** 日付データでも文字列でも 'yyyy-MM-dd' に揃える。
 *  ★2026-08-14 追加: 明細の日付は Date、集計先は書式がまちまちで、
 *    String() で比べると永遠に一致せず、同じ日が毎晩追加されていた。 */
function dkey_(v) {
  if (v === null || v === '') return '';
  var d = (v instanceof Date) ? v : new Date(v);
  if (!isNaN(d.getTime())) return Utilities.formatDate(d, TZ, 'yyyy-MM-dd');
  return String(v).trim();   // 日付として読めない時は元の文字列（fail-open）
}
```

### ② `dailyRollup` の集計キー

```js
// 変更前
var r = data[i], k = String(r['日付']);
// 変更後
var r = data[i], k = dkey_(r['日付']);
```

### ③ `dailyRollup` の既存行の突合（★重複の直接原因）

```js
// 変更前
for (var x = 0; x < ex.length; x++) have[String(ex[x][0])] = x + 2;
// 変更後
for (var x = 0; x < ex.length; x++) have[dkey_(ex[x][0])] = x + 2;
```

### ④ 朝の確認と タップゼロ の件数カウント（★件数が常に0になっていた）

```js
// 変更前（3箇所）
if (String(rows[i]['日付']) === target) n++;
if (String(ex[j][0]) === target) found = true;
if (String(rows[i]['日付']) !== today) continue;

// 変更後
if (dkey_(rows[i]['日付']) === target) n++;
if (dkey_(ex[j][0]) === target) found = true;
if (dkey_(rows[i]['日付']) !== today) continue;
```

## これで直るもの

```
・同じ日が毎晩増える            → ★既存行を見つけて上書きするようになる
・曜日が空                      → ds が '2026-08-11' になるので split('-') が効く
・朝の確認が「0件」と言い続ける   → ★実際の件数を数えるようになる
・タップゼロ警報の誤判定         → 同上
```

★**マリアのPythonが書く `2026-08-11` 形式とも一致する**ので、両方が動いていても重複しない。

---

## ★入れる順番

```
1. トリガーを止める（今夜の追加を防ぐ）
2. 上の①〜④を反映して保存
3. 既存の重複行を掃除（8/11・8/12 を1行ずつに）
4. dailyRollup を手で1回実行 → 行が増えないことを確認
5. トリガーを戻す
```

**3を先にやると、2を入れる前の実行でまた増える。**
